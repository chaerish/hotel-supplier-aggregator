# 문서화 체크리스트 (이 프로젝트 전용)

이 프로젝트는 결과물만큼 만든 과정과 AI를 어떻게 활용했는지 기록하는 걸 중요하게 여긴다. 아래는
`docs/JOURNEY.MD` Day1, Day2에서 이미 확립된 관행에서 뽑은 규칙이다.

## 1. 언제 이 스킬을 쓰는가
- 하루 작업을 마무리하며 `JOURNEY.MD`에 `Day N` 기록을 남길 때
- 설계 의사결정이 하나 확정됐을 때 (선택 / 근거 / 버린 대안)
- AI(나)와 유의미한 논의를 했을 때. 질문, 답변, 수용/수정/거부의 흐름으로
- 코드가 바뀌어 `DESIGN.md`, `README.md` 내용과 실제 구현이 어긋났을 가능성이 있을 때
- 커밋하기 직전, 문서와 코드가 잘 맞는지 마지막으로 점검할 때

## 2. JOURNEY.MD 작성 형식 (Day1/Day2에서 이미 확립된 틀. 그대로 따른다)

```
## Day N - YYYY-MM-DD (요일) - 주제

### 오늘의 목표
- [x] 완료한 항목
- [ ] 못 끝낸 항목

### 수행 내용
- 그날 실제로 한 일 (완료 여부와 무관하게 시도한 것도 포함)

### 의사결정
#### [선택한 것을 제목으로]
근거를 서술.
  - 검토했다 폐기한 대안: 무엇이었고 왜 버렸는지

### 막힌 지점 / 시행착오
- 실패나 삽질도 그대로 남긴다

### AI 활용
#### 무엇을 물었는가?
- 실제 질문
##### AI 답변을 어떻게 수용/수정/거부했는가?
- 그대로 안 쓰고 검증하거나 재판단한 지점을 구체적으로

### 참고 자료
- 링크 등 (선택)
```
Day1에는 `### 고민했던 것 / 의문점 (해결 과정)` 섹션도 있었다. 헷갈리다가 이해가 정리된 과정이 있으면 이 섹션을 추가해도 된다 (필수는 아님).

## 3. 반드시 남겨야 하는 것
- AI 활용 기록을 남긴다. 하루에 최소 1건은 "무엇을 물었는지, 어떻게 수용하거나 수정하거나 거부했는지"를 남긴다. AI를 안 쓴 날이면 그 사실과 이유를 적는다.
- 시행착오를 숨기지 않는다. 완성된 결과만 적기보다, 막힌 지점과 폐기한 대안을 그대로 남긴다.
- 설계 문서에 적은 내용은 실제 코드에 반영되어야 한다. 코드가 바뀌면 `DESIGN.md`, `README.md`도 같이 갱신했는지 확인한다. 어긋나 있으면 이 세션 안에서 바로잡거나, 최소한 다음 할 일로 기록한다.
- AI가 생성한 문장을 그대로 붙여넣지 않는다. JOURNEY.MD, DESIGN.md, README.md 어디든 검토하고 수정한 티가 나야 한다.

## 4. 문체 규칙
- 문장 안에서 em dash(`—`)를 절 연결에 쓰지 않는다. 자연스러운 연결어(그리고, 그런데, 즉, 이유는 등)나 마침표로 문장을 나눠 쓴다.
- 단어를 이어붙이는 middle dot(`·`, 예: "타임아웃·재시도")도 쓰지 않는다. "타임아웃과 재시도"처럼 풀어 쓰거나 쉼표로 나열한다.
- 이모지를 장식으로 쓰지 않는다.
- 마크다운 리스트 불릿(`- 항목`)이나 코드, 경로 표기의 하이픈은 이 규칙과 무관하다 (구조적 표기이지 문장 연결이 아님).

## 6. 작업 세션 마무리 체크리스트
- [ ] 오늘 한 일을 `수행 내용`에 적었는가
- [ ] 의사결정이 있었으면 "선택 / 근거 / 버린 대안" 3요소를 다 적었는가
- [ ] AI와 나눈 대화 중 하나 이상을 "질문 → 수용/수정/거부" 형식으로 기록했는가
- [ ] 막힌 지점과 시행착오를 숨기지 않고 적었는가
- [ ] 코드 변경이 `DESIGN.md`, `README.md`와 어긋나지 않는지 확인했는
- 가
- [ ] 커밋하기 전에 `CLAUDE.local.md`의 점검 항목도 함께 확인했는가
